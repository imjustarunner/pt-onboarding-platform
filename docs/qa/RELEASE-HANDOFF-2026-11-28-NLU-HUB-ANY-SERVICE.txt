OWNER'S SCOPE CLARIFICATION
The full tutoring Session Hub is available for NLU's individual client sessions
regardless of the selected service code/business category. Staff choose the
Hub when doing tutoring activities. Service filtering can be added later.
This supersedes the previous TUTORING-only restriction and the old VC18
expectation that NLU counseling must have only the Google Meet option.
Other agencies retain their existing meeting behavior.

RESULTING BEHAVIOR
- NLU virtual booking offers Platform Session Hub and system-generated Google
  Meet separately from the service/code/subject. Non-learning NLU bookings keep
  Google Meet as their default; an explicit Hub selection is honored. Code
  changes and format/policy loading do not silently change the NLU selection.
- The native option opens the full existing Session Hub: shared whiteboard,
  worksheet/material tools, activities, AI practice, ratings, progress and notes.
  The same full Hub is available from eligible in-person NLU appointments.
- The server resolves the stored NLU organization, including retained QA453/454
  with intact markers. A client-supplied brand cannot enable another agency.
  NLU uses the full Hub without requiring a separate tutoring rollout flag.
- The existing assigned-provider/one-student appointment boundaries remain.
  This is not a new group/class workflow, a studentless meeting, a credential
  grant, or permission to schedule a service the employee is not authorized for.
- Family access uses the actual appointment's current service, provider, agency
  and relationship. An active tutoring enrollment cannot unlock an unrelated or
  ended counseling service. Restricted relationships and revoked links stay
  restricted; full tools do not expose another service's private records.
- Native family email/SMS/portal destinations use the exact appointment's Hub
  invitation, including for non-TUTORING codes. Existing Google Meet options
  still use their system-generated per-appointment links. Calendar staff entry
  resolves to the same Hub rather than creating a second counseling room.
- A non-TUTORING activity workspace retains the actual source code and business
  type in its existing metadata. It never overwrites the booked code/price or
  reclassifies an H2014/custom-code service as TUTORING.
- Completion validates the same appointment, provider, student, source code and
  actual positive attendance interval. Settlement uses the original appointment
  and its selected-service policy. It does not use a tutor profile price or an
  automatic tutoring card charge. Retries reuse existing appointment settlement.
- Homework Help retains its existing distinct compensation path. Other service
  codes continue through their own documentation/claim/payroll workflow; using
  learning tools does not generate a tutoring payroll claim for those services.
  Activity notes do not replace required service-specific documentation.
- Canceled, changed, expired or ended sessions preserve their existing records.
  Changing a booking still closes its native media rather than treating the
  canceled appointment as completed work.
