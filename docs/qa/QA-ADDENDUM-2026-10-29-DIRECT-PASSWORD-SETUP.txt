Use the browser and QA inbox/vault. No database, code or admin access is needed.

FIRST-TIME GUARDIAN: OFFICE AND SCHOOL, ENGLISH AND SPANISH
- Complete enrollment without first creating a portal password.
- The single enrollment confirmation email must contain "Create my password"
  or "Crear mi contraseña". It should open the password-creation page directly,
  without a Forgot Password request or another email.
- Create and confirm a password, and supply a linked client's date of birth
  if the existing verification screen asks for it. Saving should sign the
  guardian in automatically to the correct portal and authorized dependents.
- Opening the email link alone must not create a password or start a session.
  The personal setup link is time-limited and single-use. A used/expired link
  must not grant access. Do not put its token or the password in evidence.
- School enrollment uses the family portal; it must not send the guardian to
  the school-staff login. Spanish email copy and button must be Spanish.

EXISTING ACCOUNT
- Enroll another child or use a guardian who already created a password during
  enrollment. The receipt button stays "Open my portal" / "Abrir mi portal"
  and opens normal sign-in. The existing password must continue to work.
- Receipt generation must not reset or replace an established password.

SIBLINGS, SECOND PARENTS AND DELIVERY
- Use the existing multi-child/second-parent cases. Each guardian's receipt
  must use that guardian's own login. Shared notification history must not
  reveal another guardian's personal setup link.
- Refreshing completion must not send another receipt or invalidate the link
  already sent. Two sibling receipts sent before setup should both lead to the
  same still-valid setup until the password is created.
- No separate setup/recovery email should be generated by this receipt change.
  Normal password-change security notices remain separate from setup emails.
- Keep explicit no-automatic-email choices in force. Do not turn on messaging
  or change a family's preferences to make a test pass.

Existing emails are historical and will not be rewritten or bulk resent.
Capture the button, sanitized destination path, successful portal landing,
delivery count and language. Never capture a password or a live setup token.
