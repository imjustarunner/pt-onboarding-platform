Changes

- Transition preparation: the production error stack came from
  assignSmartDisclosureToPortal -> currentClientUpdateRecipient ->
  assertClientCanViewOwnShared -> guardianAppointments.authorizedClient.
  Preparing a new consent now checks the exact enabled, active, unrestricted
  guardian relationship and signing permissions without requiring the portal
  to be open already or granting access to previous clinical records.
  Transition school-form preparation uses the same narrow consent-setup path.
  Clinical assessment and existing-record viewing checks remain in place.
- Overview shows all linked guardian accounts with each account's own name,
  phone and email, including when the dependent chart-type metadata is absent.
  Revoked, inactive and self-account rows are excluded from guardian cards.
- The chart Secure message action routes dependent/family contexts to the
  existing shared-family composer. It selects only a server-approved shared
  family recipient and retains the exact child and agency. The existing
  audience review, clinical restrictions and immutable historical audiences
  continue to control sending and reading. Pending portal setup, denied access
  and billing-only accounts do not gain clinical messaging access.
- Primary affiliations can be removed from the chart and import assignment
  panels. Removing the last affiliation clears the legacy organization_id,
  ends only that affiliation's roster assignments and records history.
  An active service referencing the affiliation must first be moved explicitly
  using Change provider -> School / program -> No school or program, or ended.
  The existing service assignment editor now exposes this program selector.
  Removing an affiliation does not silently remove the counselor from a service.
- Client.findById uses the same agency-specific provider projection as the
  directory. Sibling and chart clinician labels therefore use current service
  assignments, with the existing legacy fallback only when there is no service
  history. Provider identity links use the projected provider ID. Legacy owner
  IDs remain unchanged. Assigned-clinician access is returned explicitly for
  authorized chart viewers. Roster-empty copy distinguishes affiliation-specific
  rosters from the service provider shown above.
- Prospective/Current remains a separate lifecycle choice. No new automatic
  status transition or production data backfill is included.
