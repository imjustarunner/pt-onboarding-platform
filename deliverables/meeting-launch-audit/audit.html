M01 · HighPublic join metadata disclosed alternative room tokens

Public branding/redirect responses now preserve only the reference opened by the visitor. Numeric references no longer reveal stored host or participant tokens.

M02 · HighAnonymous supervision access bypassed personal invitations

Shared anonymous supervision routes remain retired. A recipient-specific invitation exchanges for a short-lived, session-limited grant; it uses the named supervisor/supervisee identity for room role and attendance without a separate app login.

M03 · HighAttendance accepted caller-supplied participant identities

Presence now authorizes the current account and derives its identity on the server. Interview candidate identity is derived from the validated interview token. Unauthenticated ordinary meetings cannot create or close another person’s attendance. Supervision time starts on a confirmed main-room connection heartbeat, not on token issuance or lobby admission.

M04 · HighOld URL roles and stale membership could affect access

Room access uses active tenant membership and the current roster. Host privileges derive from the owner/cohost assignment. Shared host URLs no longer promote schedulers. Added active membership checks to meeting workspace and activity authorization; withdrawn supervision invitees lose room access.

M05 · HighCancelled or external meetings could still request platform credentials

Token, admission and heartbeat paths reject cancelled/ended meetings and explicit non-platform locations. Authorized leave cleanup remains possible. In-person supervision cannot create a video room.

M06 · MediumShared host/participant copy controls remained in current screens

Removed role-link sharing from creation confirmation, live team meetings, supervision details/live rooms and the meeting editor. Joining remains available; new people are invited by adding them to the meeting. Clinical client invitation sharing is a separate workflow and is preserved.

M07 · MediumOld reminder schema fallbacks could ignore opt-outs

Removed fallbacks that retried without notification preferences or persisted reminder timing. Missing required columns now stop delivery instead of sending under invented defaults. Existing configured and per-event reminder paths remain disjoint.

M08 · MediumCPA and mentorship defaults were treated as ordinary huddles

Meeting settings and compensation validation now use the actual subtype in creation, editing and persistence. The editor loads subtype-specific defaults and keeps matching fallback values.

M09 · MediumActive prompts could send external meetings into platform video

Prompts use the selected Google Meet link when platform video is off, exclude in-person meetings without video, and exclude withdrawn supervision invitees.

M10 · MediumCamera tiles reverted to horizontal layouts

Earlier fixes in this task enforce square tiles in gallery, solo, featured and lobby layouts. Browser measurements verified square dimensions at desktop, tablet and mobile widths.

M11 · HighSilent or lost microphone input lacked clear recovery

Earlier fixes add microphone selection, an input meter, live-track validation, interruption warnings and microphone reconnection without restarting the camera. Simulated tests cover ended/paused/missing tracks and preserved mute state. The reported interview’s exact cause remains unconfirmed; a live headset call is required.

M12 · MediumScheduling was crowded and ambiguous

Earlier fixes combine people/groups with membership-aware search and collapsed groups, expand crowded calendar cells into readable accessible cards, replace overlapping virtual switches with a location selector, and explain all meeting types.

M13 · HighClient transcription depended on UI-only consent checks

Provider opt-in and verified signed consent are enforced at audio capture and transcription endpoints. Reuse existing agency audio_recording_consent templates; signed PDFs attach to the client file and support later sessions. Consent withdrawal stops current/future recording until signed again.

M14 · HighBrowser transcription bypassed configured processing and pause boundaries

Supervision browser speech upload is retired. Selected microphone audio is normalized to WAV (including Safari AAC), sent to configured Cloud Speech, and stored encrypted. Both participants can pause; changed revisions reject in-flight recognition. Final segments drain before host exit/note creation.

M15 · HighSupervision agreements were absent from the assignment/onboarding flow

The supplied text is versioned, agency-branded and bound to typed/drawn signatures and private PDFs. The current assigned supervisor and supervisee both sign. Required during onboarding, never prehire; scoped to clinical roles in mental-health agencies. Existing assignments are lazily created on access; a repeatable backfill command is included.

M16 · HighOff-platform supervision needed a traceable exception workflow

The Supervision tab accepts manual entries with required reason, modality and validated duration. In-person microphone transcription uses the same consent gates. Hours await current supervisor approval and pass through existing attendance/hour-credit finalization; overlapping attended/manual records are rejected.

M17 · HighClient transcripts did not feed the existing clinical writer

Recorded client transcripts call the existing Note Info/Note Aid generation controller. Long transcripts are summarized using Vertex before note generation; saved results are unsigned clinical drafts for provider review. The session stores the draft id to prevent duplicate generation on retries.

Compatibility and personal links

  • Existing room-token columns and old calendar/bookmark routes remain for compatibility. They are not invitations to share and do not independently grant ordinary meeting access.
  • Personal supervision and client invitations now act as private bearer links for their named recipient, without an app login. Treat them as private credentials: forwarding permits the recipient’s session identity. They cannot be used as app-wide login tokens. Current roster/client assignment, link rotation and expiry are rechecked on every scoped request.
  • Interview candidate guest links and clinical client/guardian invitations serve external participants and are distinct from obsolete anonymous staff-supervision access.
  • Vonage project-key compatibility and historically named roomSid/twilio_room_sid storage remain: the active video adapter uses Vonage. Removing these names without migrating stored sessions could break existing meetings.
  • Legacy stored reminder settings remain supported without bypassing notification opt-outs. Existing records are not bulk-emailed by this change.
  • Recording-rule provider functions remain unimplemented and the recording-rules endpoint fails rather than reporting success. No caller was found in the current meeting UI; recording is not certified by this audit.
